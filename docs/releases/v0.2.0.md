# Strata 0.2.0

This release is in preparation and has not been published.

## Screens owned by Paper, Folia, and Velocity

Paper server plugins and Velocity proxy plugins can open Strata screens, own their state, and receive typed input events while the matching Fabric runtime renders the interface on the player's client.
Install the `plugin` distribution for the server or proxy and keep all Strata artifacts on version 0.2.0.
Players still need the Strata Fabric runtime for their exact Minecraft version and Fabric Language Kotlin; vanilla clients cannot render Strata screens.

Use `PaperScreens.open(owner, player) { ... }` from Paper's primary thread or the player's Folia region, or `VelocityScreens.open` with a definition factory on Strata's dedicated UI thread.
Create mutable state inside these factories; Folia preserves its player ownership across region migrations.
See the [Paper guide](https://github.com/sya-ri/strata/blob/v0.2.0/docs/guides/paper.md) and [Velocity guide](https://github.com/sya-ri/strata/blob/v0.2.0/docs/guides/velocity.md) for installation, consumer dependencies, and compiled examples.

Connections negotiate the supported components and extensions before opening a screen.
State revisions, input subscriptions, and screen ownership are bound to the authenticated connection; switching servers or disabling the owning plugin releases the associated session.
Paper and Velocity screens share the client's single remote-screen slot.
Protocol translation and nested proxy integration are outside this release's contract.

## Portable reactive core and browser runtime

The API and retained core now share their implementation between JVM and JavaScript.
Existing JVM consumers retain the `strata-api` and `strata-runtime-core` coordinates; multiplatform consumers use the corresponding `-multiplatform` coordinates, whose metadata selects the platform artifacts.

The browser runtime supports native DOM text, buttons, and progress indicators, reactive updates, and adoption of deterministic initial HTML.
Use `renderWebHtml` or `renderWebDocument` to create initial content and `mountWeb` to attach an independent definition with matching initial values.
The browser profile does not yet implement the full Minecraft component set.
See the [browser build guide](https://github.com/sya-ri/strata/blob/v0.2.0/docs/development/build.md#initial-web-documents) for the supported controls and build workflow.

## Minecraft compatibility

This release adds an exact Fabric runtime for Minecraft 26.3 and retains the Minecraft 1.20 support floor.
Select the runtime for the client's exact Minecraft version; server and proxy plugins are separate artifacts.
The [compatibility reference](https://github.com/sya-ri/strata/blob/v0.2.0/docs/reference/compatibility.md) lists the client targets and required Java versions.

## Upgrading from 0.1.6

Update the API and every installed runtime together.
Retain mutable editing, selection, and navigation state outside reevaluated declarations.
Standard component-state changes now participate in reactive content observation on both common and Minecraft hosts.

Portable UUID values use Kotlin's standard UUID implementation on JavaScript while preserving native Java UUIDs and the existing player-skin API on JVM.
Custom components can opt into declaration projection and register matching server/client extensions; a missing capability rejects a remote screen instead of silently changing its behavior.
See the [projection contract](https://github.com/sya-ri/strata/blob/v0.2.0/docs/reference/declaration-projection.md) before exposing custom primitives remotely.
