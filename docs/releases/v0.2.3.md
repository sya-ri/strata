# Strata 0.2.3

Strata 0.2.3 reduces retained UI, layout, text and image-processing work, adds native item tooltips to bound Slots, and corrects high-contrast widget rendering.
These notes describe changes from public [0.2.2](https://github.com/sya-ri/strata/releases/tag/v0.2.2).
Keep all Strata artifacts on version `0.2.3` and install the Fabric runtime for your exact Minecraft version.

## Measured changes from 0.2.2

The table compares the actual Maven Central `0.2.2` API, core and headless JARs with the `0.2.3` candidate built from [commit 9270c7833](https://github.com/sya-ri/strata/tree/9270c78338462f3855ba96839cc890f0c34edfb6).
Only release documentation changed after that build.
Each value is the shared testkit's median of three independent runs on the same host, with the same compiled fixtures, harness, collector and external libraries.

The Full HD clean timed frame allocates 112 → 32 B/op, and 1024×1024 PNG encoding allocates 12.59 → 4.20 MB/op.
Fresh Full HD CPU rasters still allocate about 8.3 MB/op.

For Full HD inputs, sampled p95 increased from 18.976 to 28.192 µs for dirty retained frames (+48.6%), and from 1043.456 to 1476.608 µs for fresh CPU rasters (+41.5%).
These observations do not establish a uniform latency improvement.

**Reduction = (Before − After) / Before × 100.** Positive values mean less time or allocation; negative values mean a regression.
Percentages are rounded to one decimal place; 0.0% can include a small increase or decrease.
These are observed changes for the selected JVM workloads, without significance tests or absolute performance thresholds.

### Conditions and scope

- Windows 11, amd64, Intel Core i9-14900F, 32 logical processors, OpenJDK 25.0.2. Collection ran serially after local build work stopped.
- Every registered input for the six selected methods completed: four `RenderingBenchmark` frame/raster methods at 320×180, 854×480 and 1920×1080, and both `ColdImageBenchmark` methods at 64×64, 256×256 and 1024×1024.
- Each mode used three independent invocations per side, three one-second warm-up iterations, five one-second measurement iterations, one fork, one thread, microsecond units and the GC profiler. Side order alternated between repetitions. These are standard runs, with no quick or smoke profile.
- The shared `JmhPerformanceRunner`, `JmhWorkloadInventory` and `JmhPerformanceEvidence.compare` verified the complete selected matrix, actual parent/fork archive origins, fixed collector/harness/inputs and independent receipts. Six representative raster/PNG outputs matched byte-for-byte across both versions before timing.

PNG inputs are already resident before decoding, and encoding returns fresh bytes without writing files.
PNG decoding uses the same JDK ImageIO implementation and the unchanged public copying image factory on both sides; its observed timing differences do not establish a Strata decoder improvement.
These measurements cover JVM frame, CPU-raster and PNG operations; Minecraft presentation, GPU completion, text editing, remote round trips and browser workloads are outside this sample.
They do not establish FPS or input-to-display latency.

## Minecraft presentation

- Hovering a populated bound `Slot` in the active screen shows the complete vanilla item tooltip, including native item-provided content, advanced-tooltip settings and positioning near screen edges. Updates to the bound stack are reflected while the pointer stays still. Native carried-item eligibility still applies; `highlightable` controls the highlight independently. Unbound Slots can use the ordinary `Tooltip` component for application content. See [screens and state](https://github.com/sya-ri/strata/blob/v0.2.3/docs/guides/screens-and-state.md#connect-minecraft-resources).
- Widget profiles read sprite scaling metadata from the active resource pack so buttons and slider handles preserve the built-in high-contrast pack's borders. Newly opened screens use the selected pack after a resource reload.
- Exact sampled-image adapters also handle horizontal, vertical and combined reflection with opaque-white tint and zero cutoff. Other combinations retain ordered CPU composition where required for exact pixels; this does not enable every tint or cutoff on the GPU.
- Portable composition reuses unchanged paint branches and raster tiles, shares preparation and upload ownership, and reduces repeated sampled-source calculations. Native resource retirement waits for the corresponding Vulkan work to complete.

## Retained UI, text and images

- Retained traversal skips unrelated branches and empty child-matching work. Identical immutable modifier chains, small semantics payloads, container construction, Canvas membership and image templates avoid unnecessary intermediate copies or bookkeeping.
- Grid layout reuses measured track extents, and VirtualList reuses unchanged visible row declarations as its window moves. Existing ordering, keys, layout and state ownership remain intact.
- TextArea insertion lookup is bounded to the relevant line. Text composition, caret arrays, glyph raster storage and text-ink aggregation avoid redundant temporary storage while preserving Unicode editing and immutable output.
- CPU rasterization shares exact sampled-source weights, avoids unnecessary work for nonpainting commands and writes deterministic PNGs directly into their final storage.
- `createDrawImage(size, pixelAt)` generates an immutable image directly into private storage. The callback runs synchronously once per pixel in row-major order and is not retained; the existing array overload still copies caller-owned pixels.

## Remote screens and lifecycle

- Bounded transport and command drains stop at the first empty result or missing next sequence while preserving tick deadlines and outgoing work. Freshly decoded private fragments can transfer into native reorder queues without a second queue copy; public frame inputs retain their defensive-copy behavior.
- Remote editable membership follows current retained entries, and terminal presentation-state closure cannot reopen admission during callbacks. Font owners also remain closed across reentrant backend callbacks.
- Root-overlay anchors enforce the owning layout scope and its lifetime, rejecting anchors used from another scope or after that scope expires.

## Authoring and performance tools

The optional Detekt `DiscardedModifier` rule recognizes modifier values used by `if`, `when` and `try` expressions, avoiding false positives for returned or assigned conditional chains.
Unused branches, nonterminal expressions, `finally` results and Unit callbacks remain checked.
See the [authoring checks guide](https://github.com/sya-ri/strata/blob/v0.2.3/docs/guides/authoring-checks.md#discardedmodifier).

The [responsive panel example](https://github.com/sya-ri/strata/blob/v0.2.3/docs/guides/layout.md#center-a-responsive-panel) demonstrates centering a panel and switching between half-size and full-size layout from current viewport constraints using the public Modifier SPI.
It is application composition and does not add a specialized built-in component.

The shared performance testkit adds opt-in GPU-completion measurement on supported native adapters, more precise artifact provenance, optional per-operation JVM reports and paired JVM/browser comparison tooling.
Reports keep fixture and collector identities, unavailable metrics, unchanged controls and regressions visible; quick runs remain separate from standard evidence.
See the [performance testkit](https://github.com/sya-ri/strata/blob/v0.2.3/docs/development/performance-testkit.md) for collection and comparison contracts.

## Upgrade

Update Maven dependencies, the installed Fabric runtime and any Paper/Folia or Velocity plugin together to `0.2.3`.
Existing application screen definitions and remote protocol messages require no migration from `0.2.2`.
The supported Minecraft version matrix is unchanged; Minecraft 1.20 remains the release floor.
Update optional `strata-detekt-rules` and performance-testkit dependencies to the same release.

Runtime bridges marked `InternalStrataRuntimeApi` are opt-in implementation contracts; applications should continue using ordinary immutable images and public screen APIs.
Consumers implementing the Minecraft 26.3 `FabricVulkanDestroyedResource` bridge must also implement `strataDestroyCompletedResource()` and establish GPU completion before calling it.
Rendering improvements depend on the selected commands and adapter, and do not imply a universal FPS improvement.
