# Strata 0.3.2

Strata 0.3.2 preserves held gameplay movement when opening Fabric UI and fixes semantics for replaced virtual-list rows inside nested containers.
These notes describe changes from public 0.3.1.

## Upgrade requirements

Update Strata artifacts together to `0.3.2` and keep the Fabric runtime matched to the exact Minecraft version.

## Held movement in Fabric UI

Opening a screen with a movement-permitting input policy now preserves movement, jump, sneak and sprint bindings already held in gameplay.
The same behavior applies when a passive HUD acquires interactive input.
Previously, acquiring input cleared those bindings until the player pressed them again.

The handoff respects remapped keys and each binding's input permission without replaying queued presses or toggling sneak again.
Attack, use and discrete actions are not inherited.
Text editing, focus loss, permission changes and closing release held input; a replacement UI does not inherit the previous UI's held state.

See [game input and interaction](https://github.com/sya-ri/strata/blob/v0.3.2/docs/guides/screens-and-state.md#control-game-input) for input policies and interaction ownership.

## Fabric initialization failures

When UI content fails during initial attachment, the failed screen is removed and the original content error is preserved.
Failed attachment prepares native screen events before cleanup, allowing removal to complete before later frames can access the failed screen's released resources.

## VirtualList semantics

Scrolling a `VirtualList` inside nested containers now keeps the replacement rows in the retained semantics tree.
Ancestor summaries are refreshed when layout constraints replace the virtualized children, so semantics queries continue to include the visible rows after scrolling away and back.
