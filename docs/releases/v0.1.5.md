# Strata 0.1.5

Strata 0.1.5 adds direct state inputs, lazy projections, observed regions, and render monitoring so applications can update an open screen while retaining compatible input and scrolling nodes.
Applications keep the existing `ScreenDefinition` opening API and explicitly bind the parts of their tree that depend on changing state.

## Install

Compile application UI source against the API, then install exactly one Fabric runtime matching the active Minecraft version together with Fabric Language Kotlin:

```kotlin
dependencies {
    compileOnly("dev.s7a.strata:strata-api:0.1.5")
    modRuntimeOnly("dev.s7a.strata:strata-runtime-minecraft-fabric-<minecraft-version>:0.1.5")
    modRuntimeOnly("net.fabricmc:fabric-language-kotlin:<compatible-version>")
}
```

The consuming Mod must require Strata in `fabric.mod.json`:

```json
{
  "depends": {
    "strata": ">=0.1.5"
  }
}
```

## Observe changing regions

`Observe(source) { value -> ... }` declares a region whose callback receives the source's committed value.
Generated overloads accept one through 22 `StateSource<V>` arguments with independently inferred value types and pass their values in declaration order.
Applications supply conforming sources through the existing [StateSource contract](https://github.com/sya-ri/strata/blob/v0.1.5/docs/reference/state-sources.md); fixed values and ordinary captured Kotlin variables are not automatically reactive.

Observe owns one slot in its containing layout and accepts a modifier and optional stable key.
Its callback emits zero or one root; place an inner `Row` or `Column` around multiple components.
An empty region has zero natural size, subject to its parent's constraints and its own modifiers.
Apply parent data such as weight or alignment to Observe itself, and create child-layout parent data inside the callback's fresh layout scope.

The runtime shares one subscription and one committed snapshot per source reference identity within a retained tree.
This includes repeated arguments, nested Observe regions, and source-backed Text reading the same source.
At each frame cutoff it captures all pending observations before committing values and reconciling changed regions parent-first.
Multiple pending revisions coalesce to the newest snapshot, and equal committed values do not trigger a source-driven content evaluation.
Updates arriving after capture wait for the next frame.
Replacing the last reader's key or parent structure within a frame preserves that source instance's committed snapshot and pending notifications.
A source first referenced during deferred construction supplies its atomic subscription snapshot, which other readers in that tree reuse; subsequent notifications wait for the next cutoff.

A parent-supplied callback change also reevaluates its region even when that region's source values are unchanged, keeping captured parent values current.
Nested invalidations coalesce into one evaluation for each surviving region in the frame; a removed region does not run its pending content.
Unchanged regions reuse their retained child descriptions, and compatible keyed descendants keep their existing nodes.
Focus, text selection, IME preedit, and viewport state therefore survive compatible updates while the same screen remains open.
Changing a key or replacing a node still ends that node's ownership.

Keep editable state such as `TextAreaState`, `TextFieldState`, and scroll state outside observed callbacks.
Every callback runs on the tree owner thread with a fresh, callback-lifetime `UiScope`; it must not retain that scope or mutate its sources.
The tree releases subscriptions with no remaining reader before the frame returns, and releases all observation resources on terminal failure or close.
Source values remain application-owned and are not deep-copied.
Updates to independent sources are not an atomic application transaction; publish one immutable model through one source when multiple fields must change together.

## Source-backed text

`Text(source)` accepts both `StateSource<String>` and `StateSource<UiText>` through the same Observe mechanism.
Both forms retain the existing text layout, wrapping, style, modifier, key, and optional explicit-font choices.
The complete modifier chain belongs to the actual text node; a transparent region owns its sibling key and delegates parent data to that node.
Text resolution and wrapping run on the tree owner thread against the committed value.

Existing literal Text overloads remain available.
The source overloads use distinct JVM names, `TextStringSource` and `TextUiTextSource`, to preserve the two Kotlin value types despite generic erasure.
The [screens and state guide](https://github.com/sya-ri/strata/blob/v0.1.5/docs/guides/screens-and-state.md#observe-changing-regions) and [compiled component example](https://github.com/sya-ri/strata/blob/v0.1.5/docs/reference/components.md#observe) describe the ownership and composition contracts.

## Compatibility with 0.1.4

Prefer literal values for fixed content, direct source inputs for changing component data, retained `source.map { ... }` projections for derived display values, and narrow Observe regions for structural or layout/style changes.
Direct overloads accept mixtures of sources and literals on ProgressBar, Image, PlayerHead, Canvas, TiledImage, Slot, Button, Tab, Checkbox, Slider, CycleButton, TextField, TextArea, VirtualList, and SelectionList.
Dedicated editing and navigation state remains caller-owned; indexed list count/lookups and refresh retain their existing API.
Canvas and tiled-image source replacement does not change their dedicated frame/tile delivery contracts.

Map construction is lazy, projections support nullable values and chains, and ordinary subscriptions preserve upstream revisions even for equal results.
The UI computes each retained projection from the committed frame input and only notifies its dependents when the result differs by `==`.
Transforms must be pure and return normally; changing a parent callback still refreshes its captured content independently of source equality.

The opt-in runtime `RuntimeUiDiagnosticsOwner` capability supplies `startRenderMonitoring()` on sessions, Minecraft hosts, and Fabric screens.
It records actual content, node, subscription, and pipeline work without changing application screen definitions.
See [render monitoring](https://github.com/sya-ri/strata/blob/v0.1.5/docs/development/render-monitoring.md) for owner-thread use, bounded retention, overflow, failure evidence, and native counter interpretation.

The public API change is additive and does not require a new screen factory or reopening a screen for each source update.
Applications choose explicit observed regions rather than acquiring implicit tracking of arbitrary Kotlin reads.
Custom runtime implementations opting into the internal `StateObserverNode` SPI must provide the same source identity, frame cutoff, and owner-thread observation contracts.
Keep all Strata artifacts aligned on 0.1.5.

## Minecraft compatibility

The supported matrix remains Minecraft 1.20 through 1.20.6, Minecraft 1.21 through 1.21.11, 26.1, and 26.2.
Minecraft 1.20 through 1.20.4 use Java 17, Minecraft 1.20.5 through 1.21.11 use Java 21, and 26.1 through 26.2 use Java 25.
